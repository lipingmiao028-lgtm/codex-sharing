使用 skill-creator 创建名为 ui-test 的全局 SKILL，保存到当前用户主目录下的 .agents/skills/ui-test/。

职责：根据用户输入的测试用例文档（包含页面 URL），遍历相关页面，确认测试点，将页面操作落地为可执行的 Playwright 脚本；回归时复用已有脚本，最终输出测试报告。

技能要求：
1. 测试用例文档路径、已有测试脚本或测试项目位置、报告及证据保存位置均由调用者传入；技能不内置设计文档路径、案例页面 URL、项目名、技术栈或 output/ 目录约定。读取文档中的页面 URL、用例编号、前置条件、操作步骤与预期结果；缺少 URL 或无法执行的条件时指出缺口，不猜测补齐。
2. 先检查测试项目已有脚本及其覆盖的用例。回归测试中，已有且有效的脚本直接复用执行，不重复生成；仅为未覆盖的用例新增脚本，页面或用例变化时更新对应脚本，保留用例与脚本的对应关系。
3. 首次编写或需要调整脚本时，按输入 URL 实际访问并遍历用例涉及的页面，确认操作入口、页面元素、交互状态和测试点，不扩展到无关页面，不凭文档猜测元素定位。
4. 明确 Playwright 的工作是操作浏览器页面：打开 URL、点击、输入、选择、导航并读取页面结果；将确认过的页面操作及预期断言写成可重复执行的测试脚本，不能只生成测试说明，也不能仅调用接口代替 UI 操作。优先使用可访问名称定位，用 expect 等待结果，不用固定 sleep 掩盖时序。
5. 实际运行脚本，记录页面结果、pageerror 和相关控制台错误，失败保留截图及 trace。正常业务流程连接用例指定的真实服务，Mock 与故障注入单独标记；缺少浏览器或页面不可访问时记为阻塞或未执行，不宣称通过。
6. 最终输出测试报告：输入文档和测试 URL、执行环境与命令、用例到脚本的对应关系、复用/新增/更新的脚本、通过/失败/未执行数、失败步骤与实际结果、证据相对链接及剩余问题。发现业务缺陷先报告；按调用者明确授权修复并复测，不删除或放宽断言掩盖失败。

项目脚本、运行产物、失败 trace、报告与截图按调用者指定的位置保存；文档引用证据时使用相对链接。全局技能不绑定某个项目或网站，不操作生产数据。校验技能名称、描述、触发条件、文件引用和调用方式。
